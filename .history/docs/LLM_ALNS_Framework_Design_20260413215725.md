# 4. 基于大模型的启发式与求解算法设计

## 4.1 基于大模型的启发式算子优化机制

传统启发式算法（如大邻域搜索算法）在求解复杂车辆路径问题（VRP）时，其核心算子（破坏与修复算子）通常依赖专家经验进行人工设计。然而，面对生鲜冷链等包含多重复杂约束（如时间窗、发车成本、油耗、制冷及货损等）的场景，人工算子往往难以穷尽所有优化特征。因此，本节提出一种基于大语言模型（LLM）的启发式算子自动化优化机制，通过算法骨架与核心逻辑的分离，实现算子的智能生成、动态注入与迭代自愈。

### 4.1.1 算子自动化优化框架设计

本系统构建了一个高度解耦的**算子自动化生成与自动化微调框架**，主要包含以下核心设计：

1. **骨架与插件解耦架构（Skeleton-Plugin Architecture）**
   框架将基础的元启发式演化结构与具体的算子逻辑进行剥离。求解器骨架（Heuristic Solver Engine）负责主循环控制（如模拟退火准则、权重调节与解的合法性判定），而由 LLM 动态生成的算子则被封装为独立插件（`HeuristicPlugin`）。在运行时，插件逻辑被动态注入到骨架中，既保障了主控流程的稳定性，又赋予了底层算子无限的进化潜力。

2. **代码解析与容错注入机制（Code Normalization & Auto-Completion）**
   为避免 LLM 生成的代码引发结构性异常，系统引入了严格的规范化拼接模块。通过正则表达式提取 LLM 响应中的代码块后，系统会主动剔除并重构初始化方法（`__init__`），强制注入统一的数据依赖上下文（如车辆载重 `capacity`、距离矩阵 `dist_matrix` 等）。此外，系统内置**算子自动补全机制**，在 LLM 发生幻觉或遗漏（如缺失规定的 `greedy_insert` 等方法）时，自动注入降级控制桩（Fallback Stubs），以避免运行期爆发 `AttributeError` 中断实验。

3. **闭环执行反馈与自愈调优（Execution-Feedback Retry Loop）**
   生成的算法文本被投递至完全隔离的沙盒环境（Sandbox Subprocess）中进行独立试跑。若评估过程由于逻辑漏洞（如数组越限）或语法错误崩溃，框架将捕获完整的堆栈回溯信息（Traceback），并将其作为错误上下文反向拼接输入给 LLM。这种基于“报错-反馈-修正”的闭环重试机制，驱使 LLM 像人类开发者一样完成代码自愈，显著提升了算子生成的可用性。

### 4.1.2 Prompt 工程设计

为引导大语言模型生成符合严格约束且逻辑缜密的高级算子，本节设计了包含指令约束、数据映射及防御性规则的系统级 Prompt 工程：

1. **强约束声明与任务锚定（Strict Constraints）**
   在系统提示（System Prompt）中明确将 LLM 角色设定为资深运筹学与启发式算法工程师，并强行约束其“必须且只能”提供 5 种指定签名的 ALNS 核心方法（随机移除 `random_removal`、路线移除 `route_removal`、连续节点移除 `string_removal`、贪心插入 `greedy_insert` 及后悔插入 `regret_insert`）。禁止修改入参结构，且要求实现必须完整不可遗漏。

2. **数据结构暴露与底层挂载（Data Structure Exposure）**
   由于精确成本计算依赖于特定的项目结构，Prompt 向模型全面暴露了关键底层数据的访问协议，包括字典类型的客户信息表达格式（`id_to_customer`）、多维惩罚的距离矩阵索引方式以及全局约束参数（如需求量与最大载重）。

3. **领域特定的防御性规则（Domain-Specific Anti-Pitfalls）**
   这是保证生鲜冷链 VRP 求解精度的关键。由于本问题包含发车固定成本（$C_{11}$）、运输油耗（$C_{12}$）、制冷（$C_{13}$）、货损（$C_2$）及时间窗惩罚（$C_3$）等多项目综合成本，模型常常会陷入使用传统 TSP“距离差分公式”的误区。为此，Prompt 内置了强防御性指导，**明确禁止使用局部距离估算增量**，并提供标准代码范例，强制 LLM 无论是进行贪心还是后悔插入的增量评估，都必须调用系统的统一成本计算函数法，并动态计入增广路径所产生的新车启动固定成本。
   此外，针对 $O(N^2 \times M \times L)$ 带来的计算瓶颈，Prompt 还显式指导模型在设计`regret_insert`时采用仅记录“最佳与次佳路线最优插入点”的近似评估逻辑，而非全量枚举，从而兼顾了求解性能。

## 4.2 ALNS 求解框架设计

本项目无论是基线求解还是由 LLM 驱动的算子求解，均构建在鲁棒的自适应大邻域搜索（Adaptive Large Neighborhood Search, ALNS）底层框架之上。机制设计重点如下：

1. **多维度自适应算子池（Adaptive Operator Pool）**
   算法采用破坏与修复相交替的双向搜索机制。
   * **破坏算子（Destroy Operators）** 旨在打破局部最优困境。包含：随机移除（Random Removal，实现空间发散抽离）、路线移除（Route Removal，整车路径清空以腾出重构容量）以及连续节点移除（String Removal，破坏关联路段的同时保留部分高质量区段）。破坏比例（Destruction Degree）随寻优停滞次数（Stagnation Iterations）的增加进行动态扩展，呈现从微调到大范围震荡的自适应性。
   * **修复算子（Repair Operators）** 旨在使用更优的序列重组零散节点。包含：贪心插入（优先插入即期边际成本增加最少的客户）和后悔插入（对“如果不放在最优位置将导致次优位置成本急剧攀升”的紧迫节点优先入轨）。

2. **基于轮盘赌的算子权重动态更新机制**
   框架利用轮盘赌选择（Roulette Wheel Selection）随机抽取本轮的破坏与修复算子对。各算子权重依据其历史表现带来的解集质量进行阶段性修正，采用平滑指数更新公式：
   $$W_{new} = W_{old} \times (1 - \rho) + \text{Score} \times \rho$$
   其中系统设定平滑学习率 $\rho = 0.1$。并且为了保证种群长期的搜索多样性，算法设置了权重衰减下限（$W \ge 0.1$），避免个别算子在演化早期表现不佳而遭遇“永久饿死”。
   算法的评价指标（Score）按贡献被划分为四档奖励：
   * 发现系统全局最优解（$\sigma_1 = 33$）
   * 改善当前局部解但未破纪录（$\sigma_2 = 9$）
   * 导致解质量变差但在退火概率下被接受（$\sigma_3 = 3$）
   * 解质量变差且被拒绝（$\sigma_4 = 0$）

3. **模拟退火接受准则与停滞逃逸（Simulated Annealing & Escape Strategy）**
   为了避免搜索过程过早收敛至局部极值，本框架在评估邻域解时融入了模拟退火（Simulated Annealing）接受机理。若新生成的解成本差额 $\Delta = C_{new} - C_{current} > 0$，则算法以一定的概率接受该劣解以维持扰动：
   $$P(\text{accept}) = \exp(-\frac{\Delta}{T})$$
   * **温度初始化与降温调节**：初始温度 $T_0$ 设置为当前解成本的特定比例（取 $\max(C_{current} \times 10\%, 100)$）。降温乘数 $\alpha$ 则依据预设最大迭代次数及收敛残比（如 $2\%$）精确计算，即 $T_{i+1} = T_i \times \alpha$，确保在搜寻末期算法退化为严格的爬山搜索。
   * **重启与局部算子调优（Restart & Local Search）**：除常规演化外，系统还在内部集成了 2-opt 局部搜索优化。同时建立长程停滞监控，若算法在超过设定的总迭代周期阈值仍无任何突破，将触发全局重心重启（Restart），回退最优解基因树并阶跃回升惩罚温度，强势摆脱局部盆地。
