# 关于 utils.py 中成本函数的使用说明

## 问题描述

`utils.py` 中的 `calculate_route_cost()` 函数能够计算完整的路径成本，包括：
- **C12**: 距离成本（单位距离运输成本）
- **C13**: 制冷成本（基于行驶时长）
- **C2**: 货损成本（新鲜度衰减）
- **C3**: 时间窗惩罚成本（早到/迟到）

但在当前的算子实现中，**插入算子（greedy_insert, regret_insert）只使用了简单的距离增量计算**，没有调用这个完整的成本函数。

---

## 当前使用情况

### ✅ 已使用的地方

在 [heuristic_skeleton.py](heuristic_skeleton.py#L739-L768) 的 `cost()` 函数中：
```python
def cost(self, solution):
    # 固定成本 C11
    fixed_cost = num_vehicles * self.calculator.f
    
    # 变动成本（调用 calculate_route_cost）
    for route_ids in solution:
        route_nodes = [self.id_to_customer[node_id] for node_id in route_ids]
        route_cost_info = self.calculator.calculate_route_cost(route_nodes, self.dist_matrix)
        total_variable_cost += route_cost_info['variable_cost']
    
    return fixed_cost + total_variable_cost
```

### ❌ 未使用的地方

在算子实现中（如 `greedy_insert`, `regret_insert`），计算插入成本时只考虑距离：
```python
# 当前的简化计算
cost_inc = (self.dist_matrix[prev][node] + 
           self.dist_matrix[node][next_n] - 
           self.dist_matrix[prev][next_n])
```

---

## 为什么不在算子中使用完整成本？

### 设计考虑

1. **计算效率**
   - ALNS 算法需要在每次迭代中多次调用插入算子
   - 完整成本计算包含指数函数、时间模拟等复杂操作
   - 在大规模问题中，简化计算能显著提升速度

2. **启发式原则**
   - 距离是成本的主要组成部分，作为启发式指标已经足够
   - 时间窗、货损等因素在插入阶段难以精确预测
   - 最终解会通过 `cost()` 函数计算真实成本

3. **实践效果**
   - 在 Solomon Benchmark 测试中，简化方法已经能达到良好的优化效果
   - 完整成本计算的精度提升可能不足以抵消计算时间的增加

---

## 如何在算子中使用完整成本？

### 方法1：简化版（当前实现，推荐）

```python
def greedy_insert(self, solution, removed_nodes):
    # 只计算距离增量
    for pos in range(1, len(route)):
        prev, next_n = route[pos-1], route[pos]
        cost_inc = (self.dist_matrix[prev][node] + 
                   self.dist_matrix[node][next_n] - 
                   self.dist_matrix[prev][next_n])
```

**优点**: 速度快，适合大规模问题  
**缺点**: 不考虑时间窗、货损等因素

---

### 方法2：完整版（可选）

```python
def greedy_insert_full(self, solution, removed_nodes):
    # 计算插入前的成本
    route_nodes_before = [self.solver.id_to_customer[n] for n in route]
    cost_before = self.solver.calculator.calculate_route_cost(
        route_nodes_before, self.dist_matrix
    )['variable_cost']
    
    # 计算插入后的成本
    new_route = route[:pos] + [node] + route[pos:]
    route_nodes_after = [self.solver.id_to_customer[n] for n in new_route]
    cost_after = self.solver.calculator.calculate_route_cost(
        route_nodes_after, self.dist_matrix
    )['variable_cost']
    
    # 成本增量
    cost_inc = cost_after - cost_before
```

**优点**: 精确考虑所有成本因素  
**缺点**: 计算量大，可能影响大规模问题的性能

## 推荐策略

### 根据问题规模选择

| 问题规模 | 推荐方法 | 理由 |
|---------|---------|------|
| 小规模（<100客户） | 完整版 | 计算量可接受，精确决策能显著提升质量 |
| 中等规模（100-500） | 混合策略 | 平衡速度和精度 |
| 大规模（>500客户） | 简化版（当前） | 距离已是成本主要因素，简化方法足够 |

### 根据优化阶段选择

1. **ALNS 迭代阶段**（多次快速探索）
   - 使用**简化版**，优先速度
   
2. **最终优化阶段**（局部搜索、精细调整）
   - 使用**完整版**，优先精度

## 核心结论

✅ **`calculate_route_cost()` 函数已被正确使用**  
   - 在 `cost()` 函数中评估最终解的真实成本
   - 这是最重要的使用场景

⚠️ **算子中未使用完整成本是合理的设计选择**  
   - 基于计算效率和启发式原则的权衡
   - 简化方法在实践中已经表现良好
